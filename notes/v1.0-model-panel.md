# BioTerm-Bench v1.0 incremental model-panel protocol

The v1.0 task set is immutable; the model panel is deliberately append-only.
Adding a model, adding another attempt wave, pausing a run, or repairing a
technical failure does not change the benchmark version.

## Initial panel inventory (2026-08-27)

- **e-INFRA:** the live `/v1/models` endpoint exposed 31 IDs. Twelve are
  concrete text-generation/chat deployments and are scheduled. The remaining
  19 are embedding/reranking/audio endpoints or mutable routing aliases such as
  `auto-llm`, `coder`, and `thinker`; the discovery snapshot records them but
  they are not reproducible model identities and are not benchmarked.
- **OpenRouter:** all 35 exact model IDs found in historical local Harbor
  receipts are included, including models with earlier context, timeout, route,
  or protocol failures. Thirty-four were available at the initial sync;
  `nvidia/nemotron-nano-9b-v2` was not, so the runner records it as unavailable
  and will try it on a later invocation if it returns.
- **Local:** initially empty. Ollama or another local runtime can be appended
  tomorrow without modifying existing provider results.

The executable manifest is `configs/v1_model_panel.tsv`. Provider discovery is
snapshotted under `jobs/v1-panel-snapshots/`; those snapshots record every live
endpoint ID and every exclusion reason.

## Attempt-wave design

Every model/attempt pair is a separate 50-trial Harbor job:

```text
v1-<deployment>-a1
v1-<deployment>-a2
...
v1-<deployment>-a5
```

This avoids a monolithic k=5 job. A completed `a1` receipt is never restarted
when the target rises to k=2 or k=5. A model added later simply starts at `a1`
and catches up to the current target. Historical jobs are never mixed into v1
scores.

Primary reporting remains single-attempt mean reward. Uniform later waves
estimate reliability and support final IRT; pass@k is secondary.

## Commands

Refresh availability and append newly discovered provider identities:

```bash
python3 scripts/sync_v1_model_panel.py
```

Add a local Harbor/LiteLLM model identity later:

```bash
python3 scripts/sync_v1_model_panel.py \
  --add-local 'ollama/<exact-model-and-quantization>' \
  --local-api-base 'http://localhost:11434'
```

Start or resume the provider lanes toward k=1:

```bash
bash scripts/v1_panel_control.sh resume 1
```

Raise the target later without touching completed waves:

```bash
bash scripts/v1_panel_control.sh resume 4
```

Inspect or pause safely:

```bash
bash scripts/v1_panel_control.sh status
bash scripts/v1_panel_control.sh pause
```

The nightly supervisor runs at most one e-INFRA and one OpenRouter trial
concurrently. If local models are configured, one local lane is added. Provider
lanes and individual attempt waves remain independent.

## Recovery and provenance rules

- Before every lane, verify `configs/benchmark_v1.0_manifest.json` and all 50
  task checksums.
- Resume partial Harbor jobs from their existing directories. Never delete,
  rename, or restart a partial receipt.
- Filter and repeat operational-error trials within the same attempt wave;
  scored model failures (`reward=0`) are final observations, not retries.
- Stop a provider lane on HTTP 401/403 and renew credentials.
- On HTTP 429, cool down for 15, 30, then 60 minutes.
- Skip currently unavailable model IDs but retain them in the append-only panel.
- Keep OpenRouter spend below the runner's default cumulative $150 cap.
- Record every transition in `jobs/v1-panel-monitor.jsonl` without credentials.
- Treat identical model IDs on different providers as separate deployments and
  report provider bridges explicitly.

## Before publication

For every local deployment, record runtime, exact weights, quantization,
context limit, serving parameters, and hardware. For provider deployments,
snapshot the exact endpoint ID and availability at each run. Freeze a final
model-panel receipt only after model additions are finished; this is separate
from the already frozen v1.0 task receipt.
